# How This Repo Upgraded Itself: The Dogfooding Story

This document is the meta-narrative for the autonomous upgrade session that took
this repository from a static agent-definition repo to a self-improving one.
The orchestrator and subagents defined in this repo executed their own backlog
(`FEATURE_BACKLOG.md`) over a single session, with every change passing the
closed loop: **design → implement → review → test → deploy → validate**, plus
code-reviewer sign-off and a QA PASS before each commit.

The session's real run manifests — `mdu-05`, `mdu-06`, `mdu-07`, `mdu-08`,
`mdu-12`, and `mdu-14` — were recorded live by the orchestrator and committed
under `examples/runs/`. `mdu-01-example/` and `mdu-02-example/` are
illustrative reconstructions of the pre-ledger MDUs.

## Failure-Recovery Loops That Actually Fired

The session was not a straight line. Three real failures exercised the
autonomous recovery loops, and each was caught, root-caused, fixed, and
re-validated by the team itself:

1. **CI pip-cache failure (MDU-02).** Run `35036784682` failed on `setup-python`
   pip cache restore — a stale cache key with no dependency manifest at the repo
   root produced a package-resolution error. Root cause: caching was pointless
   (nothing to cache) and harmful (stale key). Fix: devops removed the pip-cache
   block entirely; the rerun went green in ~10s.
2. **Schema fixture break (MDU-03).** The QA permission migration changed
   `opencode.json` structure and broke an existing schema fixture. Fix:
   test-agent updated the fixture to match the new schema; the suite went green.
3. **run_ledger bugs found by tests (MDU-07).** test-agent's 36 new tests found
   two real bugs in `run_ledger.py` (a non-dict crash and an ISO-8601 lie) plus
   an `OSError` edge. Fix: just-code's bugfix round (dict guard, real ISO
   validation, OSError handling); the `xfail` markers were flipped off and the
   suite went green at 87 tests.

## Three Lessons Learned

1. **Definition changes need restart + deploy to activate.** Editing a prompt or
   `opencode.json` does nothing until the agent session restarts and the
   definitions are re-deployed (`./deploy.sh --force --rebuild`). Several fixes
   appeared "inert" until the team remembered this.
2. **Free-tier model references drift without CI.** The two broken research
   agents (`deepseek-v4-flash-free`, `north-mini-code-free`) were stale model
   names. The registry drift check (MDU-01) and CI gate 3 exist precisely
   because nothing else notices when a free model is renamed or retired.
3. **Skills + ledger + evals compound value.** Individually each is small; together
   they made the team self-documenting (ledger), self-capable (skills), and
   self-checking (evals in CI). The next upgrade session starts from a much
   stronger base than this one did.

## Cross-CLI Headless Validation (2026-09-16)

After the combined overlay build (base + user overlay) was deployed to all three
CLIs, the golden "sumdump" Python CLI task was run headless through each
orchestrator in scratch dirs. Deliverables graded PASS on opencode and claude;
grok was partial:

- **opencode** (`opencode run --agent orchestrator`): **PASS** — 10/10 tests,
  used just-code-free + test-agent-free + code-reviewer-free, made git commits,
  and wrote `runs/mdu-sumdump/manifest.json` with `harness: opencode`. Simplest
  clean implementation.
- **grok** (`grok --agent orchestrator -p`): **PARTIAL** — 17/17 tests and the
  design → implement → test → review → QA loop all passed (QA grade PASS,
  loaded the mdu-lifecycle + git-autonomy skills, `harness: grok`), but the
  session ended before the git-commit phase landed: no `.git/` was created and
  the run manifest stayed `in_progress`. A session-finalization reliability
  gap worth tracking.
- **claude** (`claude --agent orchestrator -p --dangerously-skip-permissions`):
  **PASS** — 33/33 tests (most defensive implementation), full loop including
  the devops git-commit phase and black-box QA, `harness: claude`.
- **Permission finding**: claude's FIRST attempt failed cleanly — default
  headless mode denied Write to its own scratch dir; the orchestrator reported
  BLOCKED and requested permission. Non-interactive mode needs the
  `--dangerously-skip-permissions` flag.

### Ledger Conformance Findings

The validator found all three manifests deviated from the base schema, each
differently: opencode was missing title/timestamps and used
`qa_grade: "manual-smoke-pass"`; grok was left `in_progress` with null
verification and no summary/artifacts; claude used `status: "complete"` with
`build: "n/a"`. Root cause: the orchestrator prompt references
`docs/observability.md` for the schema, which subagents cannot read in a bare
scratch dir — so they improvised. Planned fix (tracked backlog item): inline the
schema (required fields + enums) into the orchestrator prompt, then re-test
conformance.
